## Overview

- Flutter application named "noema".
- Dart code: 226 files in lib/ (175 feature, 35 core, 10 shared, 3 l10n, 3 at the root).
- Architecture: feature-based layers consisting of presentation/pages/widgets -> providers -> services/DAOs -> Drift + OpenAPI.
- Primary state management: flutter_riverpod.
- Navigation: go_router, with StatefulShellRoute for the main navigation branches.
- Local database: Drift/SQLite, database name noema_db.sqlite, schema version 9.
- Remote backend: generated OpenAPI client in ../openapi, current base at https://api.tccnoema.me.
- Internationalization: pt-BR and en through AppLocalizations; Flutter Quill is also localized.
- Generated files exist throughout the features (*.g.dart, *.freezed.dart, app_localizations*.dart).
- Run build_runner after changing Freezed models, JSON models, or Drift definitions.

## Core

### Database
- lib/core/database/database.dart
  - AppDatabase, using DriftDatabase with schema.drift.
  - schemaVersion is 9.
  - Contains incremental migrations from 3 through 9.
  - Enables PRAGMA foreign_keys.
  - Ensures manual_backup_history exists before opening.
  - Uses a Drift native connection with noema_db.
  - Contains deleteDatabase(), marked with a TODO to remove before release.
- lib/core/database/schema.drift
  - Primary source for tables and indexes.
  - Main domains: users, themes, configuration, graphs, AI tasks, notes,
    study sessions, flashcards, questions, responses, FSRS reviews,
    domain/generic logs, and manual backup history.
- lib/core/database/database_provider.dart
  - Provides the AppDatabase singleton for ProviderScope.
- Feature DAOs manage reads and writes for the schema; do not place arbitrary SQL in UI code.

## Features

### Authentication
- lib/feature/auth/
  - Login, registration, password reset, and account state.
  - auth_state_provider determines authentication for router redirects.
  - LoginService uses secure storage for the token.
  - Forms use NotifierProvider and Freezed states.
  - sign_up_provider.dart contains a TODO for code review and learning.

### Configuration
- lib/feature/config/
  - ConfigPage is divided into profile, preferences, color theme, typography,
    language, AI API keys, Google account, and manual backup sections.
  - ConfigRefreshLifecycle and configRefreshProvider coordinate reload behavior.
  - preference_storage_provider controls local-versus-device preference storage.
  - personal_ai_configuration_service manages personal AI providers.
  - The system supports up to eight concurrent AI requests, as defined by the schema and provider.

### Knowledge Graphs
- lib/feature/graph/
  - Main knowledge domain: KnowledgeGraph, GraphVersion, GraphNode, GraphEdge,
    NodeSkill, and LearningResource.
  - Pages: graph list, blank graph creation, AI graph creation, and graph details.
  - Riverpod providers cover graph state, selection, forms, paths, transforms, and temporary JSON.
  - Widgets create and edit nodes and edges and display node details.
  - Services calculate paths and Sugiyama layouts, handle gestures and learning,
    convert AI responses, and import JSON.
- import_grap_from_json.dart
  - Contains a TODO for removing temporary test-only code.

### Exercises
- lib/feature/exercises/
  - Exercise listing and response history.
- multiple_choice/
  - Create, edit, answer, and view multiple-choice questions.
  - Choice DAOs and mode providers control behavior.
- open_ended/
  - Create, edit, answer, and view open-ended questions.
  - Captures response snapshots, duration, and study session linkage.
- exercise_correction_queue.dart and queued_exercise_correction_service.dart
  - Queue exercise corrections and integrate with AI background jobs.

### Flashcards
- lib/feature/flashcards/
  - Flashcard DAO and node-based flashcard UI.
  - Integrated with /graphs/:graphId/flashcards/:nodeId routes.
  - Integrated with the FSRS and review system.

### Study Sessions
- lib/feature/study_session/
  - CRUD, detail, execution, and history for study sessions.
  - Sessions can be associated with one or more knowledge graphs.
  - session_node and study_session_question associate ordered questions
    of both multiple-choice and open-ended types.
  - Schema migration 3 created title/description, snapshots, and status fields.

### Reviews
- lib/feature/review/
  - Domain dashboard, mastery, and review queue.
  - DomainDashboardService, DomainMasteryService, ExerciseReviewQueueService,
    and FsrsReviewService.
  - review_item_state/log, fsrs_state/fsrs_review_log, and domain_log are stored in the database.
  - Ratings range from 1 through 4 and use AI, manual, automatic, and self-rating methods.

### Notes
- lib/feature/notes/
  - CRUD for notes, note versions, and note-node relationships.
  - NoteTransferService supports transferring notes between contexts.
  - NotesPage uses an automatically disposed stream provider.

### AI
- lib/feature/ai/
  - ai_content_generation_service generates content through the API.
  - ai_request_queue serializes and limits requests.
  - ai_background_task_runner executes persisted jobs.
  - Task types: node description and exercise correction.
  - Status values: PENDING, RUNNING, RETRY_WAIT, FAILED, COMPLETED, CANCELED.
  - Retry metadata, next_attempt_at, attempt_count, and last_error are persisted.
  - AiQueuePage displays the queue; the runner is observed by AppShell.

### Study Assistant
- lib/feature/study_assistant/
  - Panel with handoff support for graph, flashcard, and exercise creation.
  - Models: study_assistant_action and study_assistant_state.
  - Context service builds context from the current application state.
  - Preferences provider controls assistant settings and pinned-panel behavior.

## Observed Conventions

- Preserve generated files and regenerate them instead of editing manually:
  *.g.dart, *.freezed.dart, and app_localizations*.dart.
- Prefer small providers with a single responsibility.
- Prefer DAOs and services for persistence and remote calls.
- UI should consume AsyncValue/StreamProvider with AppLoadingView/AppErrorView/AppEmptyView.
- Navigation should use RoutePaths helpers.
- Drift migrations must be incremental and stay synchronized with schema.drift.
- Soft-delete fields exist across many records; preserve is_archived/is_active/soft_deleted behavior.
- Many timestamps are stored as Unix seconds; verify conversion in DAOs and services.
- The primary UI language is Portuguese, but user-facing text should use AppLocalizations when appropriate.
